# 학사관리 시스템 1차 MVP 기능 명세서

## 1. 기능 모듈 구성

| 모듈 | 설명 | 핵심 사용자 |
|---|---|---|
| 인증·권한 | 로그인, 로그아웃, 역할별 메뉴 및 API 통제 | 전체 |
| 기준정보 | 학년도·학기, 학과, 전공 관리 | 관리자 |
| 사용자·학적 | 계정, 학생 학적, 교수 정보 관리 | 관리자 |
| 교과·강좌 | 과목 및 학기별 개설 강좌 관리 | 관리자, 교수 |
| 수강 | 수강 신청·취소, 시간표, 수강 조정 | 학생, 관리자 |
| 출결 | 강좌별 수업일과 수강생 출결 관리 | 교수, 학생 |
| 성적 | 최종 성적 입력·제출·확정·조회 | 교수, 관리자, 학생 |
| 감사 | 주요 변경 이력 기록 및 조회 | 관리자 |

## 2. 주요 상태 정의

### 2.1 사용자 및 학적 상태

| 구분 | 값 | 설명 |
|---|---|---|
| 계정 상태 | ACTIVE | 로그인 가능 |
| 계정 상태 | INACTIVE | 로그인 불가 |
| 학적 상태 | ENROLLED | 재학 |
| 학적 상태 | LEAVE | 휴학 표시용. 1차에서는 승인 절차 없이 관리자가 변경 |
| 학적 상태 | WITHDRAWN | 자퇴 표시용. 1차에서는 승인 절차 없이 관리자가 변경 |
| 학적 상태 | GRADUATED | 졸업 표시용. 1차에서는 자동 판정하지 않음 |

### 2.2 강좌 및 성적 상태

| 구분 | 값 | 설명 |
|---|---|---|
| 강좌 상태 | OPEN | 조회 및 수강 신청 가능 |
| 강좌 상태 | CLOSED | 신규 신청 불가 |
| 성적 상태 | DRAFT | 교수가 작성·수정 가능 |
| 성적 상태 | SUBMITTED | 교수 수정 불가, 관리자 확인 가능 |
| 성적 상태 | CONFIRMED | 학생 성적표 및 취득학점에 반영 |

## 3. 핵심 기능 상세

### FN-AUTH-001 로그인 및 권한 확인

- 입력: 로그인 ID, 비밀번호
- 처리:
  1. 계정 존재 여부와 활성 상태를 확인한다.
  2. 비밀번호를 검증한다.
  3. 인증 토큰 또는 세션에 사용자 ID와 역할을 기록한다.
  4. 대표 역할에 맞는 대시보드 정보를 반환한다.
- 예외: 계정 없음, 비밀번호 불일치, 비활성 계정
- 완료 조건: 권한 없는 API 요청이 서버에서 차단된다.

### FN-LEC-001 학기별 강좌 개설

- 선행 조건: 학기, 과목, 담당 교수가 등록되어 있어야 한다.
- 입력: 학기 ID, 과목 ID, 분반, 교수 ID, 정원, 강의실, 시간표
- 처리:
  1. 필수 데이터 존재 여부를 확인한다.
  2. 정원이 1명 이상인지 확인한다.
  3. 시간표 시작·종료 교시를 검증한다.
  4. 강좌와 강좌 시간표를 저장한다.
- 결과: 학생 강좌 조회 화면과 교수 담당 강좌 화면에 표시된다.

### FN-ENR-001 수강 신청

- 선행 조건: 학생의 학적 상태가 ENROLLED이고 강좌 상태가 OPEN이어야 한다.
- 입력: 학생 ID, 강좌 ID
- 처리 순서:
  1. 현재 시각이 수강 신청 기간인지 확인한다.
  2. 동일 강좌 신청 여부를 확인한다.
  3. 강좌 잔여 정원을 트랜잭션 안에서 확인한다.
  4. 기존 신청 강좌와 시간 충돌 여부를 확인한다.
  5. 신청 후 총 학점이 학기 최대 신청 학점을 초과하는지 확인한다.
  6. 수강 신청을 저장하고 신청 인원을 증가시킨다.
- 동시성 규칙: 강좌 행 잠금 또는 원자적 조건부 갱신을 사용하여 정원 초과를 방지한다.
- 오류 코드:
  - `ENROLLMENT_PERIOD_CLOSED`
  - `ALREADY_ENROLLED`
  - `CAPACITY_EXCEEDED`
  - `SCHEDULE_CONFLICT`
  - `CREDIT_LIMIT_EXCEEDED`

### FN-ENR-002 수강 취소

- 선행 조건: 취소 가능한 기간이며 활성 수강 신청이 존재해야 한다.
- 처리:
  1. 수강 신청 상태를 CANCELED로 변경하거나 취소 시각을 기록한다.
  2. 강좌 신청 인원을 감소시킨다.
  3. 관련 DRAFT 성적 및 출결이 존재한다면 함께 비활성 처리한다.
- 결과: 시간표와 신청 학점 합계에 즉시 반영된다.

### FN-ATT-001 출결 입력

- 선행 조건: 요청 교수가 해당 강좌 담당 교수여야 한다.
- 입력: 강좌 ID, 수업일, 수강생별 출결 상태
- 출결 상태: PRESENT, LATE, ABSENT, EXCUSED
- 처리: 강좌 수강생인지 확인한 뒤 수업일·학생별 출결을 생성 또는 수정한다.
- 단순화: 1차에서는 출결 점수가 최종 성적에 자동 반영되지 않는다.

### FN-GRD-001 성적 입력 및 제출

- 선행 조건: 요청 교수가 해당 강좌 담당 교수이며 성적 상태가 DRAFT여야 한다.
- 입력: 수강생별 최종 점수(0~100), 등급
- 등급: A+, A0, B+, B0, C+, C0, D+, D0, F
- 처리:
  1. 모든 대상이 현재 수강생인지 확인한다.
  2. 점수와 등급 형식을 검증한다.
  3. 임시 저장한다.
  4. 제출 요청 시 모든 수강생의 성적 입력 여부를 확인한다.
  5. 강좌 성적 상태를 SUBMITTED로 변경하고 이력을 기록한다.

### FN-GRD-002 성적 확정 및 취득학점 반영

- 선행 조건: 강좌 성적 상태가 SUBMITTED여야 한다.
- 처리:
  1. 관리자가 성적 목록을 확인한다.
  2. 확정 시 상태를 CONFIRMED로 변경한다.
  3. F가 아닌 확정 성적의 과목 학점을 학생 취득학점 합계에 반영한다.
  4. 확정 이력을 기록한다.
- 결과: 학생 성적 조회에 해당 성적이 표시된다.

### FN-AUD-001 주요 변경 이력

- 기록 대상:
  - 계정 역할 및 활성 상태 변경
  - 관리자의 수강 추가·취소
  - 성적 제출·반려·확정
- 기록 항목: 수행자, 작업 유형, 대상 유형, 대상 ID, 변경 전·후 요약, 사유, 수행 시각
- 제한: 감사 이력은 UI에서 수정·삭제할 수 없다.

## 4. 역할별 대시보드

### 학생 대시보드

- 학생 기본 학적 정보
- 현재 학기 신청 학점
- 오늘 또는 주간 시간표
- 확정된 최근 성적 요약

### 교수 대시보드

- 현재 학기 담당 강좌 수
- 강좌별 수강 인원
- 성적 작성·제출 상태

### 관리자 대시보드

- 현재 운영 학기
- 학생·교수·강좌 수
- 수강 신청 현황
- 성적 제출·확정 현황
- 최근 주요 변경 이력

## 5. 데이터 검증 규칙

| 대상 | 검증 규칙 |
|---|---|
| 로그인 ID | 전체 계정에서 유일, 필수 |
| 학번·교번 | 각 유형 내 유일, 필수 |
| 학과·전공·과목 코드 | 유형별 유일, 영문·숫자 조합 권장 |
| 학점 | 1~6 정수 |
| 강좌 정원 | 1 이상의 정수 |
| 교시 | 시작 교시 < 종료 교시 |
| 성적 점수 | 0~100 |
| 관리자 조정 사유 | 공백 제외 5자 이상 |

## 6. 2차 확장 고려사항

- 역할 테이블과 사용자 역할 연결 구조를 유지하여 교무·재무·입학 담당 역할을 추가할 수 있게 한다.
- 학생 사진은 파일 저장소 URL 필드를 추가하는 방식으로 확장한다.
- 과목과 강좌를 분리하여 교육과정 연도 개편과 재수강 판정을 지원한다.
- 성적 이력 테이블을 추가해 정정 승인 절차를 지원한다.
- 출결과 평가항목을 연결해 최종 성적 자동 계산을 지원한다.
