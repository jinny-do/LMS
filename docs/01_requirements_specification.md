# 학사관리 시스템 1차 MVP 요구사항 명세서

## 1. 문서 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 학사관리 시스템 |
| 개발 기간 | 3주 |
| 개발 인원 | 4명 |
| 기술 스택 | Spring Boot, Vue, MySQL |
| 사용자 역할 | 학생(STUDENT), 교수(PROFESSOR), 관리자(ADMIN) |
| 1차 목표 | 한 학기의 강좌 개설부터 수강 신청, 출결, 성적 확정까지 운영 가능한 시스템 구축 |

## 2. 범위 및 원칙

### 2.1 1차 MVP 핵심 흐름

1. 관리자가 학년도·학기, 학과, 사용자, 과목을 등록한다.
2. 관리자가 특정 학기의 강좌를 개설하고 담당 교수와 시간표를 지정한다.
3. 학생이 강좌를 조회하고 수강 신청 또는 취소한다.
4. 교수는 담당 강좌의 수강생 출결과 최종 성적을 입력하고 제출한다.
5. 관리자는 제출된 성적을 확정한다.
6. 학생은 시간표, 수강 내역, 확정 성적, 총 취득학점을 조회한다.

### 2.2 1차 제외 범위

- 입학 지원 및 전형 관리
- 등록금 결제, 장학금, 환불
- 휴학·복학·자퇴·전과 승인 절차
- 재수강, 계절학기, 복수전공
- 졸업요건 판정 및 증명서 발급
- 프로필 사진 업로드
- LMS, 도서관, 회계 등 외부 시스템 연동
- 평가항목별 성적 자동 계산 및 상대평가

## 3. 공통 업무 규칙

| 규칙 ID | 규칙 |
|---|---|
| BR-001 | 사용자는 하나 이상의 역할을 가질 수 있으나 1차 UI에서는 대표 역할 하나로 접속한다. |
| BR-002 | 모든 강좌는 하나의 학년도·학기, 과목, 담당 교수에 연결되어야 한다. |
| BR-003 | 수강 신청은 해당 학기의 수강 신청 기간에만 가능하다. |
| BR-004 | 학생은 동일 강좌를 중복 신청할 수 없다. |
| BR-005 | 강좌 정원을 초과하여 수강 신청할 수 없다. |
| BR-006 | 학생은 시간이 겹치는 강좌를 동시에 신청할 수 없다. |
| BR-007 | 학생의 학기 최대 신청 학점을 초과할 수 없다. 기본값은 21학점이며 관리자가 학기별 설정한다. |
| BR-008 | 수강 취소는 수강 취소 가능 기간에만 가능하다. |
| BR-009 | 교수는 자신이 담당하는 강좌의 출결과 성적만 관리할 수 있다. |
| BR-010 | 성적 상태는 작성 중(DRAFT), 제출(SUBMITTED), 확정(CONFIRMED) 순서로 변경된다. |
| BR-011 | 교수가 제출한 성적은 수정할 수 없으며, 관리자가 반려한 경우에만 다시 수정할 수 있다. |
| BR-012 | 확정된 성적만 학생 성적표와 총 취득학점에 반영된다. |
| BR-013 | 관리자에 의한 수강 내역 조정과 성적 상태 변경은 변경 이력을 남긴다. |

## 5. 1차 완료 기준

- 세 역할이 로그인하고 권한에 맞는 기능만 사용할 수 있다.
- 관리자가 학기, 학과, 사용자, 과목, 강좌를 생성할 수 있다.
- 학생 수강 신청 시 핵심 검증 규칙이 동작하며 정원 초과가 발생하지 않는다.
- 교수는 담당 강좌의 출결과 최종 성적을 입력·제출할 수 있다.
- 관리자는 제출 성적을 확정할 수 있다.
- 학생은 확정된 성적과 총 취득학점을 조회할 수 있다.
- 발표 시나리오를 초기화된 시연 데이터로 처음부터 끝까지 수행할 수 있다.
