# 학사관리 시스템 1차 MVP 비기능 요구사항 명세서

## 1. 목적

본 문서는 3주 MVP에서 반드시 지켜야 할 품질 기준을 정의한다. 대규모 상용 대학 수준의 목표가 아니라, 시연과 제한된 실제 운영에서 데이터 오류 없이 핵심 학사 흐름을 수행할 수 있는 수준을 목표로 한다.

## 3. 공통 API 응답 원칙

### 성공 응답 예시

```json
{
  "data": {},
  "message": "요청이 처리되었습니다."
}
```

### 오류 응답 예시

```json
{
  "code": "CAPACITY_EXCEEDED",
  "message": "강좌 정원이 마감되었습니다.",
  "fieldErrors": []
}
```

## 4. MVP 품질 우선순위

1. 데이터 무결성: 정원 초과, 중복 수강, 확정 성적 변경을 차단한다.
2. 권한 통제: 다른 사용자와 역할의 데이터를 임의로 조작할 수 없게 한다.
3. 핵심 시나리오 안정성: 발표 시나리오를 반복 수행해도 동일한 결과가 나온다.
4. 사용성: 화려한 UI보다 현재 상태와 다음 행동이 명확해야 한다.
5. 확장성: 2차 기능 추가를 막지 않는 범위에서만 고려하며 과도한 추상화는 피한다.

## 5. 시연 전 필수 검증 체크리스트

- 학생·교수·관리자 계정으로 각각 로그인할 수 있다.
- 권한 없는 메뉴와 API 접근이 차단된다.
- 수강 신청 핵심 오류 메시지가 정확히 표시된다.
- 동시 수강 신청 테스트에서 정원이 초과되지 않는다.
- 성적 제출 후 교수 수정이 차단된다.
- 성적 확정 후 학생 성적표와 취득학점이 갱신된다.
- 관리자 조정과 성적 상태 변경 이력이 조회된다.
- 시연용 초기 데이터와 복구 방법이 준비되어 있다.
